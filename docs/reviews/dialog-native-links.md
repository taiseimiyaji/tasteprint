# Native Dialog links — Issue #164

On main `c782823`, four Mock/temporary-SQLite cases confirmed that Confirm → Tab skips a leading native `<a href>` to Input, and Input → Shift+Tab skips the same link to Confirm. The native link can receive focus and is visited on the first forward pass; only the manually wrapped boundary omits it. Both the shared workspace runtime and an independent React consumer importing only an actually downloaded preview-12 ZIP reproduce this at 1440px and 390px. Escape restores the trigger and drafts survive. This is an existing unverified boundary, separate from Issue #162's disabled/negative-tabIndex fix.

The only runtime change adds `a[href]` to the existing candidate selector. Negative tabIndex, native disabled controls, rendered-box filtering and nearest-dialog/close/cancel ownership guards remain unchanged. No custom widget focus policy is added.

Four regression cases load fresh independent HTML and verify actual CSS evaluation for both runtimes. Real Tab/Shift+Tab must visit the first link and wrap in both directions. Href-less anchors without an explicit tabIndex, negative-tabIndex links, disabled buttons and disabled fieldset inputs/buttons are skipped. A native link inside a disabled fieldset remains in the Tab order, matching native semantics. An inner Dialog's link boundary stays inside the inner Dialog; closing it restores the outer trigger, outer link boundary and both drafts. No Dialog operation submits the parent form. The initial test's opening-focus assumption was removed: showModal retains native behavior, and each boundary starts from an explicit control focus followed by actual keyboard input. An anchor's tabIndex property alone does not establish sequential navigation when href is absent.

The exported runtime changes, so new bundles use preview-13. A frozen preview-12 ZIP with the previous exact selector is retained byte-for-byte with its export row and Foundation history; new exports are generated and reused independently. Previous frozen versions and the strict PNG comparisons remain. Local typecheck, 178 unit tests, built smoke, four new link cases and ten existing operation/nested cases passed; the ten existing cases passed in the initial combined run, before the corrected four new cases passed separately. No diagnostic PNG captures or real AI calls were added. Issue #159 remains unresolved.

The next valuable unverified boundary is a native link hidden by `visibility: hidden`: the existing rendered-box filter alone may not describe native sequential focus. No change or reproduction is claimed for that boundary here.
