# Dialog focus eligibility and order — Issue #166

On main `1462ce0`, raw native HTML dialogs and reusable shared-runtime/actually downloaded preview-13 ZIP consumers were compared at 1440px and 390px. In each of four conditions, Confirm → Tab remained on Confirm for 16 presses when the first candidate was inside an inert subtree or had hidden visibility. Native keyboard navigation skipped those controls and included a child with an explicit visible override. Positive native control/link indexes also exposed the same candidate-order approximation: index 1 was skipped by the runtime's DOM-order loop, and reverse navigation from index 2 jumped to Confirm instead of index 1. Current application usage/frequency is unproven; these are demonstrated reusable-consumer defects.

The fix uses one private RuntimeDialog collector for the existing candidate types. It retains native disabled, negative-tabIndex and rendered-box exclusions, checks computed visibility, excludes inert nodes inside the current modal, and stably sorts positive indexes before zero/default indexes with DOM order for ties. RuntimeDialog opens through showModal, so an inert ancestor outside that modal is not incorrectly applied to its contents. Candidates owned by a nested dialog are excluded; nearest-dialog key ownership and close/cancel ownership guards remain. Positive indexes are only a consumer compatibility control, not a recommended authoring policy. No visual CSS or custom-widget selector expansion is included.

The regression uses raw native controls without a Tab handler, real Tab/Shift+Tab walks, and explicit edge starts. Four tests cover both runtimes and widths, each with baseline, inert subtree, hidden visibility/visible child override, positive ordering and modal escape from an inert ancestor. Across 40 outer and 40 nested flows, href-less/negative/disabled controls remain excluded, fieldset links remain enabled, inner Escape restores the outer control, both drafts remain and parent submissions stay zero. Native cyclic DOM-target order must match the runtime in both directions, and the runtime must continuously retain DOM focus. The native reference must also reach every expected enabled target, preventing a broken reference from making the comparison pass.

Raw native boundary navigation includes a BODY/document-focus-out stop in Chromium before returning to modal controls. This preexisting difference is recorded and excluded when comparing cyclic DOM-target order. Removing the Tab handler would change the existing continuous in-DOM wrapping contract, so the fix retains it. Evidence is bounded to this browser and the existing candidate types, not every focusable element or browser.

New exports use preview-14. A frozen preview-13 archive containing the previous collector is retained byte-for-byte together with its export row and Foundation history; new exports are generated and reused independently. Prior frozen versions and strict PNG assertions remain. Local typecheck, 179 unit tests and built smoke passed, as did the four new matrix cases and existing native-link/operation/nested regressions. Ordinary Preview search/form, Components Dialog and narrow-layout checks passed. All tests use Mock and temporary SQLite, with zero real AI calls and no new diagnostic PNG captures. Issue #159 remains separate and unresolved.
