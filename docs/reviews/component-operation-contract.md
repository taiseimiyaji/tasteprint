# Saved component operation contract — Issue #162

On main `06182c3`, four Mock/temporary-SQLite browser cases compared a saved r2 design with ordinary Preview, the shared workspace runtime and an independent consumer importing only a genuinely downloaded image-free ZIP. At 1440px and 390px, Settings/Form used the saved Input font/size, Japanese input, Select choice and Enter submission. Two consumer instances retained independent Tabs selection and ARIA ownership, Dialog title ownership, drafts and native form semantics. Disabled fields were excluded from FormData; Tabs/Dialog operations added no submissions.

The new defect was the Dialog Tab boundary. With a disabled child Button carrying `tabIndex={0}`, Confirm → Tab stayed on Confirm. With a Button carrying `tabIndex={-1}`, it moved to that programmatic-only control. Both failures reproduced in the shared runtime and real ZIP at both widths. The control selector included these elements despite their exclusion from native sequential focus navigation.

The candidate filter now excludes negative tabIndex and native disabled controls. Existing nearest-dialog and close/cancel ownership guards remain. All four fixed cases verify forward/reverse wrapping, editable Input/Select focus, Escape restoration, draft retention, unchanged submission counts and complete exported design equality. Each consumer loads a fresh HTML document and checks actual runtime CSS evaluation. Native Select key results are compared with the same raw HTML control, and explicit selection is verified separately; no custom keyboard policy is introduced.

New exports use `preview-12`; a seeded frozen preview-11 archive, export row and Foundation history remain unchanged while the new bundle is generated and reused. Existing nested Dialog, ARIA identity, CSS scope, Input size/font and strict PNG assertions are retained. No added PNG captures or comparison tolerance is used. Initial diagnostic failures from a label locator, implicit disabled submit-button semantics and an unsupported assumption about native Select popup keys were fixture issues, recorded separately from the reproduced Dialog failure.

Local validation: typecheck and 177 unit tests passed; four new operation cases and 26 existing consumer/nested/identity/scope/Input regressions passed. This is a bounded Chromium comparison, not certification of every component state or browser. The next valuable unverified boundary is a Dialog containing a normal navigation link alongside form controls. Issue #159's PNG raster cause remains separate and unresolved.
