# Reviewの検討内容と画面移動

Reviewで修正案を選び、未送信理由を入力してExportへ移動すると、戻った時に両方が消えていた。
1440px / 390pxのMock実UIで確認し、同じWorkspaceを開いている間の保持をユーザーが承認した。

## 保持する範囲

- ReviewPanelはプロジェクトWorkspaceと同じ寿命を持ち、表示していない間はDOM・iframeを描画せず、定期GETを止める。
- Inspiration / Foundation / Components / Patterns / Preview / AI Review / Exportの往復で、レビューIDと基準revisionごとの候補群・選択・未送信理由を保持する。
- 戻る時のGETは選択中の履歴を保持する。画面移動・履歴選択だけではPOSTしない。
- 新しいReviewは別の文脈を使う。以前の結果へ戻ると以前の検討内容を復元する。
- 見送りの確定を観測したら、その結果の候補群と確定済み理由を解除する。ほかの未送信理由は保持する。
- 提案を待つ間に見送りを観測したら、開始時と観測済みの未解決指摘集合が一致しない返信を候補へ復元しない。後続GETが失敗しても、確認済みの解除を保持する。複数GETは最後に開始した読取りの結果だけを反映する。
- 適用の受理後はその候補群を解除する。古い設計の候補はUIとサーバーの従来のrevision検証で拒否する。
- 概要 / プロジェクト一覧 / 共通の好み / 別プロジェクト / 再読込でWorkspaceが終了すると一時状態を解除する。永続保存・再起動復旧は提供しない。

## 処理中の移動

同じWorkspace内では、処理中の操作・失敗・応答を元のレビューに保持する。
非表示中に進行中の操作が終了した場合も、受理した結果を反映し、再表示で続けられる。
定期取得を止めても、開始済みGETや明示操作後の結果確認GETは完了し得る。

Workspace終了後の遅い応答は一時状態を復元しない。
受理済みReview適用のrevisionは、開始時のプロジェクトのQueryキャッシュへ従来の版順序保護付きで反映する。
別Workspaceの入力を置き換えない。一時状態の期限と、受理済み保存結果の表示は分ける。

## 検証と限界

`tests/review-workspace-context.e2e.ts`は全設計画面との往復、Export JSONと明示適用、履歴の分離、
見送り後の候補解除、外部設計更新によるstale拒否、4種類の処理中移動、失敗と明示再試行、
再読込・概要・プロジェクト再開での期限、別プロジェクトへ移動後の遅い提案／適用応答を確認する。
外部見送りをGETで観測した後の遅い提案・GET失敗、およびその前に開始した古いGETの返信も確認する。
実UI、Mock AI、隔離SQLiteを使い、実Codex呼出し0件を確認する。

別プロセスの未観測更新を原子的に検知する保証、永続的な候補復旧、実AIの挙動は検証しない。
入力ライフサイクルの既存回帰は別の契約を検証する。PNG159・認証6・実データ移行は対象外。
